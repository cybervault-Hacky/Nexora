# Phase 26: Projects Management & File Operations

## 1. Overview & Architectural Scope

Phase 26 focuses on **Projects Management & File Operations** as specified in the original 32-phase roadmap.

Nexora is designed as an offline-first desktop coding studio where projects on local disks can be browsed, previewed, and leveraged for conversational grounding and controlled patch generation. Phase 26 streamlines project workflows while maintaining strict security and sovereignty guarantees:
- **Zero modification without explicit apply**: All browsing, file previews, symbol searches, and patch generations remain strictly read-only. Files on disk are never altered without user review and an explicit "Apply" command.
- **Offline Sovereignty & Data Confinement**: No project code, metadata, paths, or symbol information ever leave the developer's local machine. Zero telemetry, zero cloud analytics, zero external network calls.
- **Multiple Entry Points**: Opening projects via the native OS directory picker, manual absolute path entry, or quick resumption of the most recent project.
- **Project Lifecycle Management**: Clean switching between projects, real-time rescanning/refreshing of filesystem state, and explicit project closing with honest empty states.

---

## 2. Key Capabilities & Workflow Details

### 2.1 Project Explorer & Workspace Panel
- **Native Directory Picker**: Triggers OS-level directory selection via Tauri IPC command `pick_workspace_dialog`.
- **Manual Absolute Path Input**: Accessible text input for typing or pasting Windows (`C:\...`) or POSIX (`/...`) file paths. Dispatches standard `workspace:openManual` events and direct handler triggers.
- **Recent Project Resumption**: Reads persisted `lastWorkspacePath` from local preferences and displays a 1-click resumption button when no project is currently open.
- **Search & Path Filtering**: Real-time filtering of project paths matching filenames and directory paths.
- **Context Selection**: Checkboxes allow developers to attach specific files to AI Chat prompts. Context is bounded and respects configured token limits.

### 2.2 Read-Only File Preview
- **Secure File Loading**: Preview loads file contents via `read_workspace_file_command` with bounded buffer sizes and binary detection.
- **Metadata Transparency**: Displays line counts, byte sizes, and path indicators.
- **Security Confinement**: Content is treated as untrusted data within the WebView and rendered strictly without script execution.

### 2.3 Single-File Patch Workflow
- **Review-Before-Apply**: Patches generated by AI or edited manually display structured diffs (added/removed/unchanged lines) before application.
- **Validation Pipeline**: Pre-flight validation checks path traversal attempts (`..`), sensitive files (`.env`, `.git`), binary content, and file size constraints.
- **Explicit Apply**: Original files remain untouched on disk until the developer explicitly clicks "Apply".

### 2.4 Active Project Management
- **Compact Page Header**: When a project is active, header surfaces the project name, root filesystem path, and action buttons:
  - **Switch project**: Allows opening another folder seamlessly.
  - **Refresh**: Rescans directory entries to catch external file additions, modifications, or deletions.
  - **Close**: Unloads the active project, resets selection and preview states, and returns to the honest empty state.
- **Honest Empty State**: When no project is loaded, provides clear onboarding copy, security notes, and a primary call-to-action button to open a project folder.

## 5. Security & Boundary Verification

1. **Content Security Policy (CSP)**:
   - Untrusted source code files previewed via `FilePreview` are rendered as text without eval or script execution.
   - Patches are validated for path traversal before disk application.
2. **Offline Confinement**:
   - Strictly zero network calls added.
   - All IPC calls (`set_workspace`, `read_workspace_file_command`, `close_workspace`) are confined to local Tauri backend.
3. **Memory & State Sanitation**:
   - Closing a project clears cached inventory, preview text, selected context paths, and active patch state.
