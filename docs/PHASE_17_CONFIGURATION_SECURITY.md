# Phase 17 — Configuration & Security Reference

This is the configuration inventory and validation record for the current Nexora desktop/backend architecture. It documents sources, sensitivity, defaults, required state, and validation. `.env.example` contains no live credentials; backend secrets are never given a `VITE_` name or placed in the frontend bundle.

## Environment and network endpoints

| Setting | Source / sensitivity | Required, default, and validation |
|---|---|---|
| `NEXORA_ENV` | Backend process environment; non-secret mode selector. Desktop build environment also selects a mode that is compiled into the desktop binary. | Backend debug builds default to `development`; backend release builds require an explicit `development`, `test`, or `production`. Desktop release with no build-time value is pinned to `production`; any different runtime value is rejected, so a package cannot be downgraded. Other values fail closed. |
| `NEXORA_AUTH_BIND` | Backend process environment; non-secret socket address. | Optional; default `127.0.0.1:8787`. Must be a concrete `IP:PORT` with port 1–65535. Non-loopback binding requires `NEXORA_AUTH_ALLOW_NON_LOOPBACK=true`; keep it loopback behind a local TLS reverse proxy where possible. |
| `NEXORA_AUTH_ALLOW_NON_LOOPBACK` | Backend process environment; non-secret exposure opt-in. | Optional; default `false`. Only the exact lowercase strings `true` or `false` are accepted. Setting `true` is an operator decision and does not configure CORS or a firewall. |
| `NEXORA_AUTH_DATABASE_URL` | Backend process environment/secret manager; **confidential connection string**. | Optional in development/test; required in production. Must parse as `postgres://` or `postgresql://`, include a host, and omit fragments. Production remote hosts require exactly one `sslmode` value: `require`, `verify-ca`, or `verify-full`; duplicate/conflicting values are rejected and loopback hosts are exempt. Placeholder/missing values are rejected. Errors and `Debug` output withhold the URL. |
| `NEXORA_AUTH_TEST_DATABASE_URL` | Test-only process environment; **confidential connection string**. | Optional and used only by ignored PostgreSQL integration tests. Those tests can truncate tables; point it only at a disposable, isolated database—never production. The template value is an unmistakable placeholder. No database was contacted for Phase 17. |
| `NEXORA_AUTH_API_URL` | Desktop build environment (compiled into the Rust core) and trusted desktop process environment (runtime override in development/test). | Optional; account-service calls are honestly unavailable when unset in release. Development/test precedence is runtime primary, compiled URL, then the legacy alias. Production uses only the build-time URL and rejects either runtime endpoint variable. HTTPS is required in production. HTTP is allowed only for loopback in development/test; release QA also requires `NEXORA_ALLOW_LOOPBACK_HTTP=true`. URL credentials, query, fragment, malformed paths, and production placeholders are rejected. Invalid account configuration does not block local chat. |
| `AUTH_API_BASE_URL` | Legacy desktop runtime environment alias; non-secret endpoint. | Optional development/test compatibility fallback, subject to the same URL validation. Runtime endpoint overrides are disabled in production. Prefer `NEXORA_AUTH_API_URL`. |
| `NEXORA_ALLOW_LOOPBACK_HTTP` | Desktop build/runtime environment; non-secret boolean opt-in. | Optional; default `false`. Strict `true`/`false` parsing. It cannot relax production HTTPS rules and only permits loopback HTTP in development/test; release development/test builds require explicit opt-in. |

## Authentication, email, and session policy

| Setting | Source / sensitivity | Required, default, and validation |
|---|---|---|
| `GOOGLE_OAUTH_CLIENT_ID` | Desktop build/runtime environment; **public installed-app OAuth client ID**, not a confidential credential. | Optional. The build embeds only a non-placeholder Google client-ID-shaped value; the runtime validates again. It may be overridden by trusted process environment. No Google sign-in is enabled when missing/placeholder. It is acceptable for a public client ID to be present in a desktop binary; a client secret is not. |
| `NEXORA_AUTH_GOOGLE_CLIENT_ID` | Backend process environment; public OAuth client ID. | Optional while Google sign-in is unavailable. If configured, it must be paired with the backend loopback redirect setting and not be a placeholder. |
| `NEXORA_AUTH_GOOGLE_CLIENT_SECRET` | Backend process environment/secret manager; **confidential OAuth credential**. | Optional only for the secret-less installed-app client type; backend-only if used. Placeholder values fail validation. Never include it in the desktop app, resources, `.env.example`, or a `VITE_` variable. |
| `NEXORA_AUTH_GOOGLE_REDIRECT_URI` | Backend process environment; loopback URL, not a secret. | Optional only while OAuth is unconfigured. With a client ID, it must be the supported `http://127.0.0.1/callback` base or the exact `http://127.0.0.1:<nonzero-port>/callback` form. Non-loopback redirects are rejected. The desktop binds the actual callback listener to loopback and uses PKCE/state/nonce. |
| `NEXORA_AUTH_EMAIL_PROVIDER` | Backend process environment; non-secret capability selector. | Optional; default and only supported value is `unconfigured`. This build does not send email. |
| `NEXORA_AUTH_SMTP_HOST`, `NEXORA_AUTH_SMTP_PORT`, `NEXORA_AUTH_SMTP_USERNAME`, `NEXORA_AUTH_SMTP_PASSWORD` | Backend environment only; password is confidential, other values are configuration. | Reserved but unsupported. Leave unset; any non-empty SMTP setting fails startup instead of pretending delivery is configured. |
| `NEXORA_AUTH_EMAIL_FROM` | Backend environment; address, not an authentication secret. | Optional; must be one email-shaped address of at most 254 characters. It does not activate an email transport. |
| `NEXORA_AUTH_VERIFICATION_TTL_SECONDS` | Backend environment; non-secret duration. | Optional; default 86,400 seconds; accepted range 300–604,800 seconds. |
| `NEXORA_AUTH_SESSION_TTL_SECONDS` | Backend environment; non-secret duration. | Optional; default 2,592,000 seconds; accepted range 300–31,536,000 seconds. |
| `NEXORA_AUTH_SESSION_IDLE_TTL_SECONDS` | Backend environment; non-secret duration. | Optional; default 604,800 seconds; accepted range 300–31,536,000 seconds. |
| `NEXORA_AUTH_RESET_TTL_SECONDS` | Backend environment; non-secret duration. | Optional; default 3,600 seconds; accepted range 60–604,800 seconds. |
| `NEXORA_AUTH_RATE_LIMIT_LOGIN`, `..._REGISTER`, `..._RESEND`, `..._RECOVERY` | Backend environment; non-secret policy values. | Optional; syntax `<attempts>/<window>` with `s`, `m`, or `h` suffix; attempts are 1–10,000 and window is 1–31,536,000 seconds. Code defaults when unset are login `10/15m`, register `5/60m`, resend `5/15m`, recovery `5/15m`. `.env.example` explicitly overrides these with `5/15m`, `5/1h`, `3/1h`, and `3/1h`. |

## Local inference, model artifacts, IPC, and timeouts

- There is no environment override for local inference hosts or model artifact metadata. `llama-server` is launched with a fixed `127.0.0.1` bind; the browser UI has no direct network access to it. The API key is passed by a key-file path, never as a process argument. The key file is created with exclusive `create_new` semantics, mode `0600` on Unix (Windows inherits the protected per-user application-data ACL), refused if a prior file remains, and removed on process stop/start cleanup. Key-file setup or permission errors fail closed.
- Runtime executable and model paths come from user selection/settings and are validated before launch. Ambient `PATH`, a project-directory runtime, arbitrary user-supplied remote inference endpoints, and shell interpolation are not used. Process cancellation and bounded shutdown remain unchanged.
- Mini/Sonnet IDs and artifact metadata stay in the compiled registry. Downloads are user-initiated, HTTPS-only, digest-checked against the pinned SHA-256 metadata, limited to five redirect hops, and cancellable; defaults are 15 seconds per connect, 60 seconds without data, and 250 ms cancellation polling. A failed or cancelled download is not installed.
- Auth API HTTP client: 5-second connect timeout, 10-second request timeout, redirects disabled; a client-construction error is retained as an account-service error rather than falling back to `Client::new()`. Local inference remains available.
- Google OAuth server HTTP client: 5-second connect timeout, 15-second total timeout, redirects disabled. The OAuth browser URL is allowlisted to `accounts.google.com/o/oauth2/v2/auth` and checked for the expected PKCE/state/nonce parameters and loopback callback.
- Local model load timeout is 180 seconds. Streaming uses a 600-second first-token timeout, 120-second inter-token timeout, and 400,000-character response cap. These are fixed code defaults, not remotely configurable settings.

## Session storage, logs, telemetry, frontend, and CI

- Windows account sessions use Windows Credential Manager; non-Windows sessions are process-memory only. A vault read failure is returned as an account error rather than fabricated signed-out state. Logout/account deletion surface persistent vault deletion failure and still clear cached identity. Local chat/history continues when signed out or when vault/account services are unavailable; account-required commands remain strict.
- Custom `Debug` implementations redact session tokens, passwords, personal profile fields, OAuth claims, checkout/portal capability URLs, payment IDs, database URLs, and provider secrets. Backend log scrubbing covers bearer tokens, key/value secrets, payment signatures, cookies, and connection-string user-info. No credentials are printed by the configuration check.
- UI IPC telemetry is in-memory diagnostics only; there is no configured remote telemetry/export service. The CSP keeps browser `connect-src` to Tauri IPC. Vite's development server is bound for container preview but uses an explicit preview/local host allowlist rather than `allowedHosts: true`.
- `.gitignore` excludes local `.env` files while allowing `.env.example`. `scripts/check-config-security.mjs` checks template assignments and, after Vite builds, scans frontend text assets for backend-only setting names and high-confidence credential patterns without printing matched values. The desktop build runs this check after bundling. The current Tauri bundle declares no arbitrary `bundle.resources` entries; the only configured bundle assets beyond `frontendDist` are icons. Any OAuth ID embedded in the native core is a public installed-app client ID, never a confidential backend credential.
- CI is a test/build workflow only: its workflow permissions are read-only, its third-party actions are pinned, and PostgreSQL is an ephemeral test service. Phase 17 adds no deploy, release, or publishing workflow.

## Validation status and deferred risks

Validation results in this workspace: desktop TypeScript typecheck passed; Vitest passed (88 files, 870 tests); the Vite production build and its configuration/secret scan passed; and the standalone configuration scan passed. Vite emitted non-fatal warnings for the classic `theme-init.js` script, mixed dynamic/static imports, and a 589.58 kB JavaScript chunk.

Native `cargo`, `rustc`, `rustfmt`, and Clippy are unavailable, so Rust compilation, native formatting, Clippy, and Rust unit/HTTP tests were not run. The Scalar WASM rustfmt parsed 37 changed Rust files with zero parser/formatter failures, but 22 differ from its default formatting; this is not a substitute for the repository's pinned native rustfmt check. `psql`, SQLx CLI, PostgreSQL, Docker, and Podman are unavailable, so PostgreSQL integration tests could not run; no database was contacted. Tauri native packaging/installer checks were not run. No migrations or live accounts, OAuth, or payment providers were contacted.

The existing billing plan-change integrity finding and the backend/PostgreSQL runtime-validation backlog remain deferred. Provider unavailability and an unconfigured quota policy do not make those source-level issues production-ready or establish paid entitlements.
